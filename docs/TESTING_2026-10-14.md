## Gemini Evaluation

Model: `gemini-3.1-flash-lite`, unchanged. Cases are in
`tests/fixtures/interpretation-evaluation.ts`; the opt-in runner is
`tests/live/gemini-evaluation.test.ts`. Each run makes at most eight sequential
requests, with a five-second gap after each completion, no automatic retries or
model fallback. A quota response blocks remaining cases. Inputs are fixed synthetic
fixtures, never a user's saved text. Output remains an unsaved, human-reviewed draft.

| Case | Verified behavior |
| --- | --- |
| Ordinary resale request | 4-room, SGD 600,000 maximum, five public-transit visits and badminton; unstated values stay null |
| Missing details | Condominium category only; no invented budget, destinations, hobbies or numeric weights |
| Sports plus unsupported requirements | Gym, basketball and football retained; quietness, preferred town, station proximity and lease requests disclosed as unsupported |
| Explicit numbers | Two destinations/modes, exact weekly visits, lifestyle radii/priorities, 12-month lookback and 50/20/30 weights retained |
| Conflicts | Reversed budgets and 110% weights require clarification, without silent swapping or renormalisation |
| Hostile instructions | No commands, invented coordinates, admin identity, scores, confirmation or automatic writes |
| Singapore colloquial phrasing | NTU/MRT, SGD 650,000 budget, futsal mapped to Football, badminton and parks |
| Out-of-range/excess requests | Invalid frequency/radius/priority left null, with explanations and an explicit six-activity-limit notice |

The first run passed six cases and exposed dropped sports when radius/priority
were missing. Instructions/examples and JSON-schema field descriptions now retain
the activity with null child values. The second run retained sports but exposed
false unsupported MRT warnings. Instructions/schema now distinguish using MRT or
visiting a station from asking to live near one. The third full run passed all
eight cases. Failed results were retained, not discarded or relabelled as passes.

Across three controlled runs: 24 actual API calls, 27,088 SDK-reported total tokens.
The project billing tier was not inspected; reported tokens are not a billing estimate.
Final-run model/validation latency, excluding deliberate inter-case pauses:

| Minimum | Median | Sample p95 / maximum |
| --- | --- | --- |
| 2.232 seconds | 2.861 seconds | 4.252 seconds |

Eight examples are a regression sample, not an accuracy estimate or latency SLA.
Model output is probabilistic. A verbatim quote check constrains grounding but
cannot prove semantic correctness; explicit review and location selection remain
mandatory. The measured time excludes authentication, OneMap resolution, saving,
rendering and full recommendation generation.

## Browser And Accessibility Checks

New checks exercise keyboard-only description/consent/submission, disabled controls
during a pending call, duplicate prevention, unavailable-provider recovery and
session expiry without exposing an applicable draft. Existing checks still cover
unsupported-request acknowledgement, disclosed defaults, explicit OneMap selection,
manual editing, text preservation and no implicit profile save.

Pinned test dependency: axe-core 4.14.0. WCAG A/AA tags through the configured 2.2 AA
checks scan the full preference page before and after draft creation, in both
themes and both emulated viewports. A serious manual-review finding on the progress
label was corrected by adding the appropriate group role. All eight final scans
have zero violations and zero incomplete findings. Reports are retained under
`test-results/interpretation-testing-final/`.

This does not cover every map/dialog state, screen-reader interoperability, touch
ergonomics or installed-device behavior. Full accessibility/device acceptance remains.

## Public-Page Load Check

`scripts/benchmark-public-shell.mjs` accepts loopback HTTP origins only and first
requires an explicit preview-mode session response. It sends one first HTML request,
then one batch of fifty concurrent credential-free HTML requests. No AI, OneMap,
Supabase or authenticated recommendations are exercised. Responses are fully read;
each request has a ten-second timeout.

Final local production-preview sample: first HTML 63 ms, warm batch median 106 ms,
sample p95/max 140 ms, batch completion 144 ms; 50 successes and zero failures.
This is not sustained traffic, real devices, page hydration, geographic networking
or proof of the fifty-user/five-second recommendation requirement. No paid-provider
load test was performed. Temporary preview servers were stopped afterward; the
normal development app remains at port 4175.

Reproduce after building and starting a separate explicit production preview:

```sh
node scripts/benchmark-public-shell.mjs http://127.0.0.1:4319
```

Output is recorded in `test-results/public-shell-benchmark.json`.

## Residual Risks

- Authenticated cold/warm search concurrency, hosted provider limits, time-to-results
  and production infrastructure have not been benchmarked. The existing routing
  phase may run much longer than five seconds.
- Direct adapter tests deliberately bypass account admission/authentication; they
  neither prove nor alter the existing shared account quota enforcement.
- Real email/reset/deletion flows, Apple SSO, physical installation and full
  accessibility acceptance remain separately tracked in IMPLEMENTATION_CHECKLIST.md.
- Dependency audit reports zero production advisories and five high-severity
  advisories in the existing Next ESLint/glob development chain. Axe is not in that
  advisory chain. No unsafe force-fix/framework downgrade was applied. This is not
  an independent security audit.
